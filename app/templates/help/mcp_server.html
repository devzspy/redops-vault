MCP Server & AI Agent Access

RedOps Vault exposes a JSON API at /api/v1, authenticated with Bearer API keys instead of the cookie session this web UI uses, and ships a companion MCP server on top of it — so an AI agent (Claude, or any other MCP client) can drive the full engagement lifecycle directly: create/update engagements, log findings, upload/download loot, record kill chain activity and infrastructure, track credentials, manage the task checklist, and map ATT&CK techniques. Admin (user management) and Backups are intentionally left out of both the API and the MCP tools — those stay human-only.

1. Create an API key

The agent authenticates as a real user, so give it its own account:

  1. Log in as an admin and go to Users, create a user with the agent role (behaves like operator — full working access — but keeps agent-driven activity distinguishable from human operators in the audit trail). An existing operator/admin account works too if you'd rather reuse one.
  2. Log in as that user and go to API Keys, click Generate Key, and copy the token shown — it's only displayed once (rov_...).

2. Run the MCP server

pip install -r requirements.txt   # picks up mcp + httpx
export REDOPS_API_KEY=rov_...
python mcp_server/server.py

It talks to http://localhost:5000/api/v1 by default; set REDOPS_API_BASE_URL if the app runs elsewhere. It speaks the standard MCP stdio transport, so in practice your MCP client launches it for you rather than you running it by hand — the command above is mainly useful for a quick manual smoke test (with an MCP inspector) or debugging.

3. Point an MCP client at it

The repo ships a project-level .mcp.json for Claude Code:

{
  "mcpServers": {
    "redops-vault": {
      "command": "python",
      "args": ["mcp_server/server.py"],
      "env": {
        "REDOPS_API_BASE_URL": "http://localhost:5000/api/v1",
        "REDOPS_API_KEY": "${REDOPS_API_KEY}"
      }
    }
  }
}

Export REDOPS_API_KEY in your shell and (re)start Claude Code from the repo directory — the redops-vault tools show up automatically. For other MCP clients (Claude Desktop, etc.), add an equivalent server entry to their own config using the same command/env.

Loot upload/download tools take a local file path rather than embedding file bytes in the tool call, since loot files can be many GB — the path is resolved on whichever machine is running mcp_server/server.py.

The agent's access mirrors whichever user account issued the key: an agent/operator/admin key gets full read/write access to every engagement, while a blueteam key is read-only and restricted to assigned engagements, same as in the web UI. Treat an API key like a password — anyone holding it can act as that user through the API; revoke it at API Keys if it's ever exposed.
